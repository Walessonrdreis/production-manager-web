# Correção: Isolamento de Limpeza de Lista Vazia no Sync da Etapa 20

- **Data:** 20/05/2026
- **Bug:** Um produto/ordem que já havia avançado de etapa no Omie (saiu do estágio 20) estava sendo exibido para sempre no Controle de Produção como pendente (na aba principal), muitas vezes com a data de produção em vermelho (atrasada). Além disso, como os pedidos detalhados vinham da API em tempo real (que já não os continha), a visualização da tela de detalhes de produto ficava quebrada, exibindo "Não encontramos pedidos detalhados para este item", e a ordem não subia para o Histórico de forma autônoma.
- **Causa Raiz:** O motor temporal de sincronia (`SyncOrdersUseCase`) contava com uma validação defensiva `if (validOrderIds.size > 0)` antes de iniciar a purga de ordens antigas localmente. No cenário em que a etapa 20 do Omie ficasse completamente vazia (retornando `0` pedidos integrados do Upstream), a lista `validOrderIds` voltava como vazia (`size === 0`), fazendo com que o algoritmo ignorasse seu bloco de limpeza. Dessa forma, as últimas ordens concluídas permaneciam assombrosamente ancoradas na memória do Banco de Dados local.
- **Como foi corrigido:** O bloqueio `if (validOrderIds.size > 0)` foi gentilmente removido. O comparador `docsToDelete = allOrders.filter(o => !validOrderIds.has(o.id))` já protege e mapeia perfeitamente a diferença. Caso a API devolva ZERO ordens e existam ordens em cache, todas elas serão mapeadas em `docsToDelete` corretamente (já que o Set vazio resultará em intersecções falsas), migrando seus itens para o histórico e deletando a persistência redundante.
- **Como evitar no futuro:** Sempre tratar falhas de rede (`throw`/`AppError`) antes de checar tamanhos de arranjos em rotinas de espelhamento total (Sync by Upsert/Diff); se a operação de captação completou sem estourar nenhum `Catch`, então os registros vazios são intencionais e representam verdadeiramente que não há mais nenhuma carga ativa. O fato de `fetchFromExternalAPI` falhar lançando um erro impede de deletarmos falsamente o banco local em casos de instabilidade da rede Omie.
