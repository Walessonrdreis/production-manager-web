# Implementação: Reversão de Baixa Automática da Etapa 20 (v1.0.0)

## Problema / Objetivo
Quando um pedido sai da Etapa 20 (Produção) via Omie, o sistema automaticamente registra no banco de dados que as peças daquele pedido foram produzidas (`ProducedRecord`). No entanto, se o usuário mover o pedido de volta para a Etapa 20 por acidente (retornando a ordem de venda para produção), as peças criadas automaticamente não eram excluídas, marcando os itens daquele pedido como já produzidos.

## Solução Implementada
1. Fornecer um marcador único aos eventos de baixa gerados via sincronização da Omie.
2. Ao realizar o carregamento dos pedidos na Etapa 20 (`SyncOrdersUseCase`), identificar se a ordem de venda e o cliente retornaram.
3. Deletar os registros de `ProducedRecord` correspondentes àquele pedido que possuam o marcador pré-fixo gerado automaticamente pelo algoritmo.
