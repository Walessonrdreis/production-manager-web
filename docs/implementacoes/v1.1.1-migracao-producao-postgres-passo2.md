# Migração da Produção para Postgres (Prisma) - Passo 2

## Objetivo
Refatorar os casos de uso de Produção para suportar tanto leitura híbrida (API Externa e Banco de Dados Interno) quanto operações de gravação unicamente baseadas no banco de dados interno (ou enviando via rotas híbridas).

## O que foi feito
- Adaptamos `apps/api/src/modules/production/application/use-cases/ProductionUseCases.ts` implementando a intercalação de dados entre a API de Produção Externa Render com as query do Prisma em `GetProducedUseCase` e `GetSchedulesUseCase`.
- Foram introduzidas requisições diretas de ID únicas: `GetProducedByIdUseCase` e `GetScheduleByIdUseCase`, também garantindo fallback para consultar o cache externo em caso de falha da busca de IDs do Prisma.
- Adicionadas as rotas específicas `/produced/:id` e `/schedules/:id` para sanar endpoints necessários pelo cliente (frontend).
