# Plano de Implementação: Centralização do Motor de Agregação da Produção (v4.18.0)

## Problema / Motivação
Atualmente, as lógicas de agregação dos totais da Etapa 20 de produção (processo de somar as quantidades dos itens dentro de cada pedido) e as interações mais complexas estavam descentralizadas: o backend entregava dados pouco processados ou o frontend acabava assumindo funções de banco de dados e motor de soma (via `TrackingLogic.ts`).
Além disso, o nome do módulo "dashboard" tem um caráter muito genérico, pouco condizente com a especificidade operacional do controle de produção.

## Solução Proposta

Esta refatoração transfere definitivamente a inteligência de agregação da Etapa 20 para nossa própria API, simplificando o escopo do frontend e preparando o terreno para métricas cruzadas no futuro.

### 1. Refatoração do Módulo na API (Mudança de Responsabilidade)
- **Local:** `apps/api/src/modules/dashboard/application/use-cases/DashboardUseCases.ts` (ou a nova pasta renomeada).
- **Ação:** Em vez de retornar os pedidos parseados e crus para frente, a API fará a varredura nos itens (`order.items`), organizará e fará a soma (`totalQuantity`) por produto (`description`).
- **Retorno Esperado:** O endpoint `/stage20/totals` passa a retornar o objeto agregado que o frontend precisa de fato:
  ```json
  {
    "data": [
      { "description": "Produto A", "totalQuantity": 50 },
      { "description": "Produto B", "totalQuantity": 30 }
    ],
    "totalItems": 80
  }
  ```

### 2. Limpeza do Frontend (Dumb UI)
- **Local:** `apps/web/src/features/production/domain/TrackingLogic.ts`
- **Ação:** Remover as lógicas pesadas de `aggregateStage20Totals`. O frontend apenas requisitará o endpoint, receberá a resposta estruturada e renderizará a página. Isso aumenta a performance no lado do cliente.

### 3. Melhoria na Nomenclatura (Opcional, porém recomendado)
Para garantir maior objetividade (Regra 14 e Arquitetura):
- **O módulo da API:** Renomear `dashboard` para `production-control` (pois é o Controle da Produção da etapa 20, deixando o nome "dashboard" livre no futuro para painéis financeiros, etc.).
- **O feature do Frontend:** Pode ser mantido como `production` ou também padronizado para `production-control`.
