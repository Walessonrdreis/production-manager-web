# Plano de Refatoração: Motor de Agregação da Produção (Etapa 20)

**Versão Base:** v4.19.0
**Status:** AGUARDANDO EXECUÇÃO

## Objetivo
Desfazer o acoplamento precipitado onde um módulo redundante (`production-control`) foi criado para alocar lógica de agregação. O objetivo é mover todo o processamento de consolidação de demandas da Etapa 20 (Omie) do Frontend para a API Backend, inserindo o Casos de Uso no módulo correto e já existente (`production`), garantindo performance no lado do cliente e respeito ao Princípio de Responsabilidade Única (SRP) e separação de Domínio.

## Passos da Execução Estrita (Passo a Passo)
*Nenhum passo deve ser avançado sem a aprovação explícita do usuário.*

### Passo 1: Backend - Domínio (Migrar UseCase)
- **Ação:** Criar ou Mover o caso de uso (ex: `AggregateProductionDemandsUseCase.ts` ou adaptar `ProductionUseCases.ts`) para dentro da aplicação do módulo `production` (`apps/api/src/modules/production/application/use-cases/`).
- **Detalhes:** Esta rotina executará a leitura de `prisma.order.findMany()`, processando, consolidando e agrupando as quantidades por Produto, devolvendo ao fim um array padronizado em JSON.
- **Status:** **AGUARDANDO**

### Passo 2: Backend - Endpoints (Rotas e Controller)
- **Ação:** Criar/Plugar o Controller à rota correspondente no módulo de Produção: `/api/production/stage20/totals`.
- **Detalhes:** Garantir que este endpoint exponha a lista limpa vinda do `AggregateProductionDemandsUseCase`, sem causar devolução de arrays ocultos no payload.
- **Status:** **AGUARDANDO**

### Passo 3: Frontend - Infra (Apontamento do Endpoint)
- **Ação:** Atualizar o endpoint consumido no frontend.
- **Arquivos Afetados:** `apps/web/src/features/production/infra/ProductionRepository.ts` (e o mapeamento em `endpoints.ts`).
- **Detalhes:** Apontar o fetch diretamente para a nova rota de serviços da API: `/production/stage20/totals`.
- **Status:** **AGUARDANDO**

### Passo 4: Frontend - UI (Limpeza de Logica no Browser)
- **Ação:** Reduzir radicalmente o processamento na camada View/Domain lógico do cliente.
- **Arquivos Afetados:** `apps/web/src/features/production/domain/TrackingLogic.ts` e/ou os reducers que consolidavam os itens brutos de pedidos.
- **Detalhes:** Remover o motor de agregação assíncrono. O Frontend passará apenas a receber o array tratado via React Query e injetar (imprimir) na tabela da visualização (`MonitoringPage` / `MonitoringTable`).
- **Status:** **AGUARDANDO**

### Passo 5: Limpeza Arquitetural
- **Ação:** Remover as pastas criadas precipitadamente e que quebram a consistência do repositório.
- **Arquivos/Diretórios Afetados:** Deletar integralmente o módulo sub-utilizado e recém nascido `apps/api/src/modules/production-control`.
- **Status:** **AGUARDANDO**
