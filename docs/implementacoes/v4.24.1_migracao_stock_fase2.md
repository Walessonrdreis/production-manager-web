# Implementação: Migração Stock — Fase 2 (Shadow Read)

**Versão:** v4.24.1
**Data:** 2026-05-21
**Classificação:** Refatoração local / Infra de migração (Fase 2 — Shadow Read)

## O que mudou
- Adicionado modelo de consulta `ProductStock` ao `schema.prisma`.
- Criado o servico interno silencioso `StockShadowReadService` para execução paralela de leitura.
- Injetada chamada assíncrona (`setTimeout`) para execução do shadow read dentro de `GetStocksUseCase.execute()`.

## Por que mudou
- Validação silenciosa e em tempo real dos dados entre os dois bancos (legado e principal).
- Comparação exata das chaves (omieCode), quantidades (stockQuantity/legacy quantity) e amostragem de dados sem afetar a resposta do usuário.
- Cumprimento da restrição que obriga a leitura paralela antes de desligar o banco legado.

## Como validar
- Os logs apresentarão a seção: `[Shadow Read - Stock] Comparison Results` durante os fetches de estoques, onde estarão registrados volumes originais e legados, incluindo possíveis divergências detectadas.
- Se o banco legado não for encontrado (ex: em dev ou se variável for removida), os logs apresentarão `WARN - Legacy database not available. Skipping comparison.` sem quebrar nenhuma sub-rotina.

## Como desfazer (Rollback)
1. Remover a injeção do `setTimeout` em `GetStocksUseCase`.
2. Excluir o arquivo `StockShadowReadService.ts` do módulo correspondente.
