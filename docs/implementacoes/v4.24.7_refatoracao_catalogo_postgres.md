# Implementação: Refatoração de Catálogo via Postgres (API 2)
**Versão:** v4.24.7
**Data:** 28/05/2026

## 1. Descrição
O objetivo desta implementação foi desativar o consumo da API 1 (via chamadas HTTP) para a listagem do Catálogo (`OmieProduct`) e passar a consumir nativamente os dados da API 1 diretamente do banco de dados compartilhado em Postgres via Prisma. 

## 2. Arquivos Alterados
- `apps/api/prisma/schema.prisma`
- `apps/api/src/modules/catalog/application/use-cases/CatalogUseCases.ts`
- `apps/api/src/modules/catalog/infrastructure/integrations/catalog.adapter.ts`
- `PROJECT_SUMMARY.md`

## 3. Detalhes Técnicos
1. **Mapeamento:** Adicionado o model `OmieProduct` e `ProductStock` ao schema Prisma, apontando respectivamente para `OmieProduct` e `product_stock`. Correção da coluna `sku` para suportar nulls (`String?`).
2. **Refatoração Use Case:** Modificamos o `GetCatalogListUseCase` para abandonar o fetch Axios do `ProductsAdapter.fetchList()`. 
3. **Migração do Prisma Query:** Foi injetada a consulta `prisma.omieProduct.findMany({ include: { productStock: true }, where: { active: true } })`.
4. **Adapter:** Dentro do próprio Use Case, o payload bruto (`rawPayload`) é decodificado e planificado. Informações essenciais `stock` e `minStock` são derivadas da relação `productStock` e os unificadores primários da UI são subscritos (garantia do adapter em devolver a interface em que a SPA react se apoia de forma irrestrita seguindo as regras de Estabilidade e Contrato de API).
5. **Remoção de Código Obsoleto:** Acesso ao list via HTTP do `catalog.adapter.ts` (`fetchList`) foi limpo.
