# Implementação: Otimização de Sync Stock (Cache Local Postgres)
**Versão:** v4.24.8
**Data:** 28/05/2026

## 1. Descrição
O objetivo desta etapa foi resolver a ação atrelada ao botão "Atualizar Estoque" no frontend para que não houvesse mais requisições indiretas para o Omie na API 1 (preservando o isolamento e delegando isso aos jobs já existentes por lá), otimizando ao máximo o desempenho visual de UI. O refresh passa a buscar diretamente o state local atualizado via Postgre `product_stock`.

## 2. Arquivos Alterados
- `apps/api/src/modules/catalog/application/use-cases/CatalogUseCases.ts`
- `apps/api/src/modules/catalog/infrastructure/integrations/catalog.adapter.ts`
- `apps/web/src/hooks/catalog/useSyncCatalog.ts`

## 3. Detalhes Técnicos
1. **Refatoração no Use Case Principal:** Alteramos `RefreshCatalogStockUseCase` (API 2) para realizar um fetch leve `.findMany` na entidade `productStock` do Prisma, retornando o modelo básico e formatado (`code`, `stock`, `minStock`) e descartando a chamada HTTP de `adapter.fetchStockRefresh()`.
2. **Atualização Otimizada em Cliente:** O Frontend agora intercepta o sucesso em `useSyncStock` e efetua uma mutação direta (update in-place da querie) no state principal através de `queryClient.setQueryData(['products-raw'])`.
3. O `queryClient.invalidateQueries` foi removido. Isso garante que a UI incorpore as atualizações imediatas de estoque obtidas da API sem precisar refazer download da carga densa do catálogo de milhares de mercadorias.
