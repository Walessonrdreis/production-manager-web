# Implementação: Nova Página de Ordens de Produção (com Strategy Pattern) - v4.26.0

## Contexto e Objetivo
Iniciando a migração estruturada das Cargas de Trabalho no frontend, foi criada a nova página de Ordens de Produção.
Para garantir estabilidade, desacoplamento e isolamento de estado, seguimos a "Regra 21: Simulação de Integrações (Strategy & Gateways)" do AGENTS.md.

## O que foi feito
1. **Contratos (types/op.ts e api/contract.ts):** Definição estrita das tipagens de Ordem de Produção e a interface de serviço (`IProductionOrderService`) que dita as operações suportadas.
2. **Implementações (Real vs Fake):**
   - **Fake:** `FakeProductionOrderService` gerenciando os estados na memória via `localStorage`, emulando os fluxos e latências do banco e API remotos.
   - **Real:** `RealProductionOrderService` configurado com endpoints (ex: `fetch('/api/production-orders')`), base estrutural que em breve fará ligações com a API2 atualizada.
3. **Gateway Unificado (api/gateway.ts):** A injeção da implementação correta é centralizada via variável de ambiente `VITE_USE_FAKE_OP_API=true` que devolve a Factory sem espalhar condicionais na view.
4. **Custom Hook (hooks/useProductionOrders.ts):** Encapsulamento responsivo de `isLoading`, `orders` e `error`. Aciona o Gateway diretamente e disponibiliza para a UI apenas ações concretas.
5. **Views Limpas (views/ e components/):** Telas construídas com ignorância total da infraestrutura, consumindo apenas o que os construtores fornecem. Usam Tailwind. O design foi integrado no Router na nova rota `/v2/production-orders` que poderá ser chamada assim que ativada pelo ambiente.
