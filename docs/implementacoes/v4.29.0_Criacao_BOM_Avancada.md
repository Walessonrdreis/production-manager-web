# Implementação V4.29.0 - Assistente Avançado de Formulação de Receitas (BOM)

## 1. Visão Geral
Esta etapa foca na evolução da montagem da Estrutura de Produto (Bill of Materials - BOM).
O sistema oferecerá duas modalidades de inserção de itens para os usuários:
1. **Adição Direta (Padrão):** O usuário busca um produto já existente no catálogo do Omie, adiciona a quantidade fixa e salva (fluxo CRUD normal).
2. **Assistente de Receita (Formulação Baseada em Peso):** O usuário preenche os ingredientes base da produção como numa receita real. O sistema calcula a participação de cada item, aplica perdas (se existirem) e **normaliza todos os valores para compor exatamente 1 KG** de produto faturado.

## 2. Regras de Negócio e Domínio

### 2.1. Controle Rígido de Unidades de Medida
Para garantir total consistência matemática na normalização de 1 KG da receita, apenas medidas predeterminadas são aceitas para insumos estruturais:
- **Unidades Métricas Permitidas:** `g`, `kg`, `ml`, `l`.
- **Equivalência Volumétrica:** `ml` e `l` irão adotar uma paridade padrão com as medidas de massa (1:1), para fins de balanceamento da matriz percentual, assumindo aproximação por densidade básica.
- **Unidades Bloqueadas:** Expressões subjetivas como "caixa", "balde", "batelada" são bloqueadas no Assistente de Receita, pois impedem a extração fracional precisa do peso correspondente.

### 2.2. O Caso Único das Embalagens (`un`)
- Itens de composição que não são manipulados quimicamente/fisicamente não devem entrar no somatório de peso da receita.
- Esses itens devem ser marcados com a flag de natureza **"Embalagem"**.
- Embalagens abrem a exceção de usar a unidade `un` (Unidade).
- Seu comportamento: Serão mantidas na lista listadas linearmente e seu valor não é submetido à "regra de 3" com base nas massas. Elas entram como constantes atadas à "porção gerada" da OP para fins estritos de baixa de estoque.

### 2.3. Matemática de Normalização (Sempre para Base de 1KG)
O algoritmo de conversão rodará no frontend sem onerar a API pesadamente. 
**Processo Iterativo:**
1. Separar a matriz em `Insumos Base` e `Embalagens`.
2. Converter toda a lista de Insumos Base em `Kg` (ex: 500g vira 0.5kg).
3. Somar todos os Insumos Base para obter a **Massa Total Bruta**.
4. Executar cálculo percentual sobre cada Insumo: `% no Todo = (Quantidade do Insumo / Massa Total Bruta)`.
5. Substituir as quantidades das proporções pela necessidade base de 1KG (`Qtde Final BOM = 1 * % do Insumo`).
6. **Fator de Perda:** (Opcional) Caso o usuário defina uma porcentagem de perda (Ex: Evaporação de 10% da massa total na cocção). Para render 1 KG líquido, você precisa iniciar com `1 KG / (1 - Perda)`. Todas as proporções de insumos seguem matematicamente elevadas por este coeficiente de defasagem.

### 2.4. Resolução de Entidades Omie
Como as receitas podem agir num paradigma "rascunho", o sistema DEVE tentar vincular magicamente o nome da linha digitada ao Catálogo de Produtos.
- **Match Automático:** O nome bate com produto existente? Linha atrelada silenciosamente à Omie.
- **Divergência / Sem Match:** A linha entra em estado de Alerta no "Assistente".
- O usuário deve realizar uma Ação Reparadora para cada linha sem match:
  - **Associar:** Abre combo-box puxando lista de Produtos do banco.
  - **Criar Novo:** Abre atalho para Drawer de Produto, criando e automaticamente resolvendo o match para a linha.
